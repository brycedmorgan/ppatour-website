# Team page + Bryce Morgan page — build plan and roadmap

Bryce, 9/22: *"I want every employee listed on the PPA Tour website, so you can
see who works on the travel side and who works on the event side… even the staff
that travels and sets up the events. I also want my own page and story… I want to
start ranking number one for my own name across my own site and the PPA Tour site."*

Hidden until Bryce says go. Two deliverables, one data spine:

1. **`/team`** — every employee, grouped by what they do, with a "travels the
   tour" marker, and a page per person.
2. **`/team/bryce-morgan`** — the long-form story, built as the entity page that
   Google should treat as *the* Bryce Morgan, paired with brycedmorgan.com.

---

## 1. Where the data comes from (nothing hand-typed)

| Field | Source | Notes |
|---|---|---|
| Name, title, department, location, hire date | **Jackalope ADP roster** (`ziff/roster.js`, 158 people, 4 BUs) | Already imported from ADP; `scripts/import-adp-directory.py` regenerates it. Legal names (James Pardoe) → need a **preferred-name** overlay. |
| Headshot | **Slack** via Jackalope `/api/hr/slack-avatars` (email-matched, custom photos only) | Good enough for the grid on day one. Real headshots come later (§4). |
| "Travels the tour" + events worked | **Jackalope travel assignments** (`travelseed.js` / travel ops, per-event person + team + role rows) | Derive: anyone with ≥1 on-site assignment this season is road crew; count = events worked. The pride stat. |
| Bio, hometown, first PPA event, favorite stop, socials, opt-out | **Self-service card in Jackalope** (new "My card" under the person page / myjack) | This is the consent step. HR (Kate) never collects 158 bios by hand. |

**Public JSON = `lib/data/team.json`**, generated by `scripts/import-team.mjs`
from a new Jackalope endpoint `/api/hr/public-team` (token-gated, returns only the
public fields). **Never ship** email, reportsTo, hire date, home city, category.
Public fields: `slug, name, title, group, brand, location (HQ label only), photo,
bio, since (year), onTheRoad, eventsWorked, socials`.

### Decisions — settled by Bryce 9/22

- **UPA only on ppatour.com** (88 people). Pickleball Central, Pickleball Play
  Solutions, Pickleball Inc / Pickleball Link staff stay off "for now".
- **PPA vs MLP.** ADP cannot tell them apart (one title in 88 says "MLP"), so the
  export carries a `brand` field: `ppa | mlp | both`. Default `ppa` for every
  UPA row; Bryce/Kate set `mlp` for the people who traditionally work only MLP,
  and `both` for the crossover. The same export feeds both sites:
  - **ppatour.com `/team`** renders `ppa` + `both`.
  - **majorleaguepickleball.co `/team`** (`~/pickleball/mlp-website`, same
    Next.js shape) renders `mlp` + `both`. Same components, ported.
  - Crossover people appear on both, with the other brand as a small tag.
- **Still open:** interns and part-time (12) — recommendation is show them; and
  opt-out honored without questions (recommended).

## 2. Routes and visibility

- `/team` — grouped grid, filter chips (group · Travels the tour · HQ), search.
  Same card component as `/athletes` so it looks native.
- `/team/[slug]` — photo, title, group, "with the tour since 2021", events
  worked, bio, socials, "Works with" (same-group peers). Person JSON-LD on every
  page (`worksFor: PPA Tour`).
- Linked from `/about` (LINKS card "Meet the Team"), the About mega-panel, footer.
- **Hidden state, three stages, one flag file** (`lib/team-launch.ts`, imports
  nothing, same rule as `europe-launch.ts`):
  1. **Gated** (now → consent collected): HTTP Basic in `proxy.ts`, like Paddle
     Lab. A directory of real names and faces is not "unlisted" material before
     people have opted in.
  2. **Unlisted** (staff preview week): reachable by link, `noindex`, out of
     sitemap and nav. Staff review their own card from the Slack announcement.
  3. **Public**: flip `TEAM_PUBLIC = true` → nav, footer, sitemap, indexable.
- ⚠ Bryce's page is the exception: it goes **public first** (§3). It does not wait
  for the directory.

## 5. Ranking #1 for "Bryce Morgan"

**Today's SERP (9/22):** the bare query is owned by Mercedes Bryce Morgan
(Wikipedia + IMDb, a film director), a Snell & Wilmer partner, an RSM partner,
and college athletes. **The qualified queries ("Bryce Morgan pickleball / PPA")
already return brycedmorgan.com, LinkedIn, The Org, SportsTravel.** So the job is
(a) own every qualified query outright, then (b) become the strongest entity for
the bare name. Honest targets: #1 for the qualified queries in 60–90 days; top 3
and a Knowledge Panel for the bare name in ~6 months. Wikipedia is not on the
table yet (notability); **Wikidata is**, and it feeds the panel.

Playbook, in order:

1. **One entity, two homes.** ppatour.com/team/bryce-morgan and brycedmorgan.com
   carry the *same* `Person` JSON-LD: same name, jobTitle, `worksFor`,
   `alumniOf` (Arizona State), `sameAs` → LinkedIn, The Org, brycedmorgan.com ↔
   ppatour.com page, X, Instagram, SportsTravel profile. Each links to the other
   in the body, not just the footer.
2. **brycedmorgan.com becomes the personal hub, not a Stripe-verification
   page.** Title `Bryce Morgan — President & CMO, PPA Tour`; H1 is the name;
   add `/story` (same story, his voice), `/press`, `/talks`; keep the consulting
   section. It already ranks; give Google more to rank.
3. **Bylines.** Every ppatour.com news post Bryce writes gets an author block
   linking to his page; `author` JSON-LD on those articles. Ten posts over the
   fall is ten internal links from indexed pages.
4. **Outside links that already exist, fixed to point at the page:** The Org,
   ZoomInfo/RocketReach (claim, correct title), Racquet X speaker page, PPA press
   releases on PR Newswire, MLP/UPA sites, podcast show notes. Ask each for a
   link to `/team/bryce-morgan`, not the homepage.
5. **Wikidata item** for Bryce Morgan (pickleball executive) with the same sameAs
   set. Then claim the Knowledge Panel when it appears.
6. **Measure:** Search Console on both domains, filter query contains
   "bryce morgan"; note position weekly in `docs/notes.md`. GA4 rule from
   `ANALYTICS.md` still applies.
